# Agent Note: 高级模型媒体能力需要四个完整层级

Status: implemented

[English](2026-08-30-advanced-model-media-capability-boundaries.md) | 中文

## 问题

Harness 可以持久存储不透明的 PDF、音频文件或视频，其提供方无关内容类型也包含 `FileBlock`。这些事实很容易被误解为模型原生支持。它们只能证明用户可以附加、保留、回放、导出和下载字节；不能证明适配器会把这些字节放入提供方请求，也不能证明提供方会解释它们。

输出侧也有相同歧义。`ImageBlock` 与角色无关，附件存储可以保留生成的图片字节，客户端也能渲染助手图片引用。已安装的 pi-ai 包还暴露独立的图片生成 API。这些事实都不会让图片输出自动进入当前聊天流；不透明文件存储也不提供音频播放或音频输出约定。

因此，真实的能力声明必须区分持久存储、规范模型内容、提供方协议支持和产品渲染。把它们混为一体会产生错误肯定的能力元数据、持久准入之后才出现的提供方错误，或无法经受回放的输出。

## 决策

只有该方向所需的每个层级都完整时，原生媒体能力才存在：

1. **持久存储**接纳受限字节、返回不可变引用，并在读取时验证标识与长度。
2. **规范模型内容**在提供方无关内容与能力元数据中点名模态，而且每个模型可见引用都能从会话日志和不可变对象存储重建。
3. **适配器协议支持**把规范块转换为精确提供方路由正式支持的请求或响应形式，不静默丢弃字节，也不依赖无类型的 payload 补丁。
4. **产品渲染与输出持久化**安全地展示持久引用；生成媒体必须先提交，助手块或消息之后才能变为可见。

存储不等于协议支持，规范块不等于协议支持，UI 就绪也不等于提供方支持。模型元数据只声明所选适配器与精确路由已经实现的交集。

### 当前能力矩阵

| 方向 | 持久存储 | 规范模型内容 | 当前适配器协议 | UI 与回放 |
| --- | --- | --- | --- | --- |
| 通用文件或 PDF 输入 | 已通过不透明 `FileAttachmentRef` 完成；PDF 仅由声明的 `application/pdf` 区分。 | 已通过 `FileBlock` 和输入模态 `file` 完成；不支持的路由收到确定性元数据文本。 | 不支持。没有生产适配器序列化 `FileBlock` 字节或通用文件 id。 | 已完成惰性文件卡片与强制下载；不内联解释 PDF。 |
| 音频输入 | 字节可以作为不透明通用文件保留。 | 缺失：没有 `AudioBlock` 或 `audio` 输入模态。 | 不支持。 | 通用文件卡片可以下载字节；没有原生音频展示约定。 |
| 视频输入 | 字节可以作为不透明通用文件保留。 | 缺失：没有 `VideoBlock` 或 `video` 输入模态。 | 不支持。 | 通用文件卡片可以下载字节；没有原生视频展示约定。 |
| 图片输出 | 生产方提交经验证的栅格字节时，已通过 `ImageAttachmentRef` 完成。 | `ImageBlock` 与角色无关，可用于助手内容，但模型目录没有输出模态声明。 | 聊天适配器不支持：没有生产适配器会在发出助手内容前取得并提交生成的图片字节。 | 助手图片折叠与渲染接受持久 `ImageBlock`；这种就绪状态不认证任何生产方。 |
| 音频输出 | 字节可以使用不透明文件存储。 | 缺失：没有 `AudioBlock` 或输出模态声明。 | 不支持。 | 没有音频播放器或音频专用回放约定。 |

[不透明通用文件附件](../feature/2026-08-29-opaque-generic-file-attachments.zh.md)拥有文件准入、存储、元数据回退和安全下载。[Web 多模态图片输入与持久附件](../feature/2026-07-22-web-multimodal-image-input-and-durable-attachments.zh.md)拥有图片规范化、`ImageBlock` 和先持久化再写事件的顺序。本 note 拥有“这两项基础都不认证提供方协议”的规则。

### pi-ai 0.82.1 是上游限制，不能靠推断绕过

已安装的 `@earendil-works/pi-ai` 0.82.1 聊天类型把 `Model.input` 限制为 `text | image`。用户消息只包含 `TextContent | ImageContent`；助手聊天消息只包含文本、思考和工具调用。`dsh-llm-pi-ai` 遵循该 API：它在转换前投影不支持的持久模态，经附件服务解析图片，并构造只含文本和图片的 pi-ai 上下文。因此，`FileBlock` 会变成确定性元数据文本，而不是提供方字节。

pi-ai 经独立图片生成 API 暴露 `ImagesModel`、`ImagesContext` 和 `AssistantImages`，其输出为文本或图片。Harness 聊天适配器调用 `Models.streamSimple()` 并翻译其聊天事件流；它不会把该独立 API 挂载为助手聊天输出。使用图片 API 需要一个单独拥有责任的消费方，或一个在发布前持久化返回字节的显式聊天输出集成。依赖中存在该 API 并不构成路由能力。

DeepSeek 直接适配器中名为 `type: 'file'` 的协议部分同样不是通用文件支持。它只会在附件服务从 `ImageBlock` 建立受限 `RequestImageAttachment` 之后产生；Files API id 是图片的一种表示。其序列化器没有 `FileBlock` 分支，因此同一路径不会传输 PDF。

现有 pi-ai 模态声明在其支持范围内仍然真实：[pi-ai 模型自行声明输入模态](2026-08-12-pi-ai-route-default-input-modalities.zh.md)，未声明输入仍为文本。配置不能拓宽已安装 pi-ai 的聊天类型，也不能让 Harness 转换器携带其无法表示的块。

### 未来适配器的成立条件

只有以下陈述全部成立，提供方适配器才报告新的原生媒体能力：

- 提供方文档化 API 与适配器的类型化请求或响应表示能够携带该模态。模型名称、catalog 布尔值、HTTP 成功、通用 payload 钩子或不透明上传端点，都不能证明模型推理消费了这些字节。
- 精确路由与模型分别发布输入和输出能力。未报告模态的发现结果保持未知或保守地视为不支持；不能从名称推断并升级。
- 输入序列化解析规范持久引用，执行提供方专用的数量、大小、媒体和时间限制，并发出文档规定的精确协议形式。不支持的路由保留共享的确定性回退，不能丢弃块。
- 输出处理限制并验证提供方字节，经附件服务提交后才发出完整助手块。提供方 URL、base64、临时路径和文件 id 永远不会成为规范会话内容。
- 会话回放、fork、导出、压缩、token 计算和客户端渲染必须保留新块或显式拒绝。只存在于实时流中的生成输出并不完整。
- 序列化器测试检查精确请求体，否定测试证明不支持的路由收不到字节，会话持久化测试重建持久块，已组装的无密钥 snapshot 覆盖用户可见行为。真实提供方测试还需证明隐藏媒体内容影响响应，或返回字节可以按声明输出解码；仅有状态码不足以证明能力。

按 MIME 接受任意文件的提供方 API 可以让 PDF 复用现有 `FileBlock`，无需 `PdfBlock`。只有当前适配器或消费方需要音频与视频语义时，才增加专用规范块；将其字节保留为 `FileAttachmentRef` 始终是有效存储，但不能单独证明需要新的模型内容类型。输出能力元数据独立于 `inputModalities`，因为接受图片和生成图片是相互独立的提供方属性。

## 备选方案

**把每个已存储文件都视为模型原生输入。** 被否决，因为存储证明字节身份，不证明请求序列化或提供方解释。这会把实现缺口变成错误肯定的能力元数据，并把拒绝推迟到持久准入之后。

**在类型化适配器转换之外修补提供方 payload。** 被否决，因为无类型 payload 补丁无法修复缺失的规范内容、回放、响应事件和逐协议转换义务。它还会在依赖提供方专用未文档化字段时宣称通用支持。

**把 `FileBlock` 永久作为每种音频与视频 API 的规范类型。** 保留它作为不透明存储表示，但否决其作为通用模型内容规则。有些提供方接受任意文件，另一些要求音频或视频专用部分、元数据、限制和响应事件。第一个真实消费方决定 `FileBlock` 是否足够，或是否需要专用块。

**把预处理或生成工具称为模型原生模态支持。** 被否决。转录、帧提取、OCR、TTS 或图片生成工具可以自身形成完整能力，但模型接收的是工具结果而非原生请求媒体，能力元数据必须保留这一区别。

**自动把 pi-ai 独立图片 API 暴露为聊天输出。** 被否决，因为它有独立模型注册表、请求操作和终止结果，而不是聊天事件流。在聊天输出集成共同拥有选择、取消、持久化、会话事件和渲染之前，它应位于显式消费方之后。

## 影响

用户可以附加并保留任意文件，产品不会假装所选模型已经读取它们。PDF 在不支持的路由上变成稳定元数据，仍可供后来的文件能力路由使用；音频和视频保持可下载的不透明文件。当前聊天路由不声明原生 PDF／文件、音频或视频输入，也不声明图片或音频输出，除非精确适配器完成对应矩阵行。

这种保守策略会让已经可用的提供方功能在适配器实现并验证之前保持不可用，但失败会留在本地且可理解，而不是在模型可见状态提交后才出现。它也让后续工作保持精确：PDF 复用 `FileBlock`；图片输出复用 `ImageBlock` 与附件存储；音频和视频只在已实现协议需要时增加规范类型。

该矩阵描述的是架构完整性，不是永久产品上限。pi-ai 上游版本只有在其类型化聊天或媒体 API 经相同的持久层与用户可见层完成集成时才能解除阻塞；仅升级依赖不会改变 Harness 的任何能力声明。
