# Agent Note: Model-facing jev_decide tool over the TypeSafe AI System One API

Status: implemented

English | [中文](2026-09-28-tool-jev.zh.md)

## Problem

The harness needed machine-native decisions — routing, ranking, extraction, urgency checks — where an LLM prompt-and-parse round is slow, expensive, and unreliable. The fork's automation and triage flows ask for typed answers a caller can branch on, with an estimate of how much to trust each one.

## Decision

Add `packages/web/tool-jev` exposing one `jev_decide` tool: the model sends a state plus atomic questions (`choice` from named options, `score` on a rubric, `noul` truth assessment) and receives typed answers with probabilities and calibrated confidence from the TypeSafe (Jev) System One API.

- The API key is read from `TYPESAFE_API_KEY` only at execution time; it never rides config, tool arguments, or logs. A missing key fails the call with a structured error instead of silently disabling the tool.
- `questions` arrive as an array of `{ name, type, instructions, criteria }` rows because the value-schema DSL has no per-key map schema; `parseJevArgs` enforces the constraints the DSL cannot express (non-blank state, unique names, primitive-specific criteria).
- The response `answers` object is returned as `answersJson` — lossless stringified JSON — so the canonical value stays inside the lossless JSON subset the output DSL enforces.
- Two sibling integration paths ship beside the tool: a local stdio MCP server (`jev-mcp`) exposing the same capability as `mcp__jev__jev_decide`, and the official TypeSafe agent skill for authoring automation against the API. When the native tool lacks its environment key, the model degrades to the MCP path on its own, observed live in end-to-end runs.

## Alternatives considered

- Calling the System One API inline from plugin code without a tool: leaves the model blind to the capability and forbids conversational use.
- Waiting for an upstream implementation: the upstream has no TypeSafe integration, and the local need is immediate.
- MCP-only integration: adds a process hop for no benefit and hides the capability behind a generated namespace.

## Consequences

- The bundle now depends on an external decision API; its availability is bounded by `timeoutMs` (default 15s) and the tool is concurrency-safe.
- Catalog maintenance: the tool joins `TOOL_PACKAGES` in the catalog generator and the bilingual tool catalog; the zh side mirrors the section manually (the generator writes EN only).
- Until the next promote, the production profile loads the tool from the development worktree build through the profile patch; the patch entry switches to the workspace package when the release includes it.

## Testing

- `packages/web/tool-jev/tests/tool-jev.spec.ts`: 7 tests (parse rules, criteria validation, name uniqueness, registration, live-shaped call with a stubbed fetch).
- End-to-end, twice, against the real API from a production session: the model called the native tool (noul 0.97 on a deadline-risk state) and, in an earlier environment-less run, degraded to the MCP tool (noul 0.83) and synthesized both answers for the user.
