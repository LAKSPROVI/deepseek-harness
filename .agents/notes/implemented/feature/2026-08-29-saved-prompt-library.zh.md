# Agent Note: Web 客户端中的持久提示词库

Status: implemented

[English](2026-08-29-saved-prompt-library.md) | 中文

## 问题

人们会反复使用同一段指令。一份评审清单、一套写作规范、一组固定约束、一段能让模型给出可用回答的框架说明——每一段都要凭记忆重新敲一遍，或者从产品完全不知情的草稿文件里粘贴过来。Web 客户端没有任何地方可以保存它们，因此用户打磨了数月的文本完全存在于 harness 之外。

保存它们并不是一个浏览器存储问题。精心整理的提示词必须能在清空缓存、换用另一个浏览器和重装之后存活，而部署本身已经拥有一份由 Host 写入、用户也可以打开的持久用户偏好文档。缺的是其中的一个命名空间，以及提示词库需要的三个浏览器界面：一个用来编辑列表，一个在撰写时可以触达，还有一个把选中的提示词放进正在写的消息里。

最后这一项正是保存提示词类功能通常出错的地方。已保存的提示词是用户先前写下的文本，而不是产品可以据此行动的指令：插入操作必须把发送这一动作留在人手里，而提示词库自身的记账信息——标题、身份、顺序，乃至某条提示词被使用过这一事实——都不能变成模型会读到的内容。

## 决策

`@deepseek-ai/dsh-client-ui-prompt-library` 是一个同时包含 Host 半边和浏览器半边的包。Host 半边注册持久的 `prompt-library` 设置命名空间；浏览器半边通过 `ctx.settingsScope` 绑定该命名空间，并在一个由 `apply` 拥有的存储之上安装三个 slot 条目。

| 半边 | 注册内容 | 提供能力 |
|---|---|---|
| Host（`src/index.ts`） | 在 `ctx.settings` 上注册 `prompt-library` 命名空间 | schema、各项限制，以及序列化 schema 无法表达的校验器 |
| 浏览器：设置页 | `settings.section` | 对有序列表的完整创建、编辑与删除 |
| 浏览器：启动按钮 | `conversation.input.left` | 一个打开选择器的紧凑输入区控件 |
| 浏览器：浮层 | `conversation.input.overlay` | 一个可搜索、用于插入单条提示词的选择器 |

一条提示词是 `{ id, title, body }`，数组顺序即显示顺序。注册本身就意味着该命名空间可配置，因此提示词库不需要在 api-proxy 中做任何改动，也不需要写入任何暴露列表（[插件自有的设置界面](../architecture/2026-08-12-plugin-owned-settings-surface.zh.md)）。

### 各项限制由 Host 拥有

Host 最多接受 100 条提示词、120 个字符的标题、12,000 个字符的正文，以及整个列表 200,000 个标题与正文字符；id 必须唯一，且任何字段都不得为空。数量与单字段长度是 schema 事实。唯一性与总量上限无法在序列化 schema 中表达，因此它们运行在命名空间校验器中，直接拒绝写入，而不是任由文档增长到客户端无法在内存中持有并搜索的规模。

这些限制作用于完整列表，而不是正在编辑的那一条提示词，因为持久化的是完整列表，浮层过滤的也是完整列表。浏览器在 `validatePromptList` 中重复了每一项限制以提供即时表单反馈，而 Host 注册仍是权威：客户端校验的存在，是为了让用户在输入时就知道标题过长，而不是由它来判定这次写入是否合法。

### 持久化只有一个来源

设置 scope 是提示词唯一的保存位置。本包既不读也不写 `localStorage`、`sessionStorage`、`IndexedDB` 或 cookie，因此持久的答案就是部署的设置提供方所持有的内容——在文件提供方下，就是用户自己的 [`settings.yaml`](../../../../packages/settings/settings-file/README.zh.md) 中的 `prompts` 数组。

当 scope 报告 `memory` 模式或文档不可写时，提示词库不会降级为一份私有的浏览器副本。存储会把该快照投影为明确的不可用状态：设置页显示一行持久化不可用说明，并禁用创建、编辑与删除，启动按钮也被禁用。因此远程浏览器会话看到的是没有提示词库，而不是一个会悄悄遗忘的提示词库——后者正是本地回退会造成的失败：用户整理好一份列表，而它在其他每个客户端和下一台机器上都不存在。

三个条目读取的是同一个在 `apply` 中创建、并由 scope 同步的存储，因此选择器、启动按钮和设置页不可能对"保存了什么"或"保存是否可用"产生分歧。

### 选择写入草稿，绝不写入消息

选择一条提示词只会以完整的下一份草稿调用 `inputActions.setDraft`，此外别无动作。空草稿直接变为正文；非空草稿变为原有文本、两个换行符，然后是正文。本包绝不调用 `submit`。

用两个换行符而不是一个，因为输入区发送的是 Markdown，单个换行会把已保存的提示词和用户先前输入的内容并成同一个段落。采用追加而不是替换，因为草稿属于用户，而一个会丢弃已输入文本的选择器，等于把数据丢失藏在了一次点击背后。

`trimStart()` 后以 `/` 开头的正文会在设置页编辑器和选择器中都带上警告。这样的正文在输入区里读起来像斜杠命令，而把它插入非空草稿会产生一行看起来像命令、却按文本发送的内容。该警告陈述这一不匹配；它不会阻止保存，因为一条确实在讲斜杠命令的提示词，也是用户可能想要的提示词。

### 提示词文本是用户数据，不是 agent 上下文

提示词库保存的任何内容都不会自行到达模型或会话日志。id、标题、顺序、条目数、搜索查询，以及某条提示词被选中这一事实，都只存在于浏览器一侧，不产生任何会话事件。正文恰好在人把它所写入的那份草稿提交时才对模型可见，而此时普通的 user message 路径将其作为输入文本携带，没有任何标记把它与用户写下的其他内容区分开。

这让该功能无需新增会话事件就落在"模型可见即被记录"规则之内：在人发送之前，不存在任何模型可见的内容；在人发送之后，既有事件已经承载了完整文本。

## 已考虑的替代方案

**把提示词库存入 `localStorage`。** 不需要 Host 注册、不需要设置命名空间、不需要写入路径，而且在内存设置模式下也能工作——而已发布的功能在该模式下会自行禁用。它同时会让提示词库随缓存清空而丢失，对第二个浏览器和用户下一台机器都不可见，并且把用户撰写的持久内容放在备份、导出和设置页都看不到的地方。设置文档是产品已经拥有、用户也可以打开的持久存储。

**在设置文档不可用时回退到 `localStorage`。** 这能让功能在远程与内存模式下继续可用。它也会让持久性变成一件悄然有条件的事：同一套界面有时跨机器保留、有时不保留，而用户无从分辨；在回退中整理的提示词会在下一次连接状态变化时消失。因此这里改为明确陈述不可用状态。

**插入并在同一次操作中提交。** 已保存的提示词往往就是一条完整指令，因此直接发送读起来像是显而易见的捷径。它同时把发送决定从人手里拿走、丢弃用户已经输入的内容，并把列表里的一次误点变成一次模型请求。选择只写入草稿然后停止；由人来发送。

**替换草稿而不是追加。** 更简单，也符合"这条提示词就是消息"的理解。它同时会悄悄删除用户输入的文本，而这恰恰是选择器绝不能做的事。带空行的追加两者都保留，并且在 Markdown 中读起来是对的。

**在会话中记录提示词元数据——消息上的 id、标题或"来自提示词库"标记。** 这能提供来源、分析能力，以及展示哪条已保存提示词产生了某一轮次的能力。它同时把提示词库的记账信息放进持久日志并送到模型面前——在请求中，一个标题是没有解释的噪声——并且要为一个没有任何模型行为依赖的事实新增会话事件。只有用户发送的文本会被记录，并且作为文本记录。

**让浏览器拥有各项限制。** 客户端可以独自执行这些限制并省掉命名空间校验器。Host 文档可以通过其他途径写入，因此这些限制就会退化为建议：手工编辑的 `settings.yaml` 可以持有一份任何客户端都无法渲染和搜索的列表。校验器在写入处拒绝。

**用一个合并界面代替三个条目。** 一个不带输入区入口的单一设置页可以减少 slot 数量。它同时把提示词库放在距离其使用场景三次点击之外；启动按钮和浮层之所以存在，是因为插入这件事属于草稿旁边。

## 测试

包的约定测试覆盖了经内存提供方进行的 Host 注册与释放、重复 id 与总量上限的拒绝、恰好达到与超过每项限制的数量与单字段校验、向空草稿与非空草稿的草稿组合（且从不调用 `submit`）、斜杠前缀判定，以及不可用状态向共享存储的投影。一个真实 Loader 组合测试从仅用于测试的 `cordis.yml` 启动 Host 半边，并通过 `ctx.settings` 执行命名空间 CRUD。

## 后果

用户在设置文档中保有一份持久、有序的提示词库，可从输入区触达，并把提示词插入正在撰写的消息中而无需离开会话。由于存储就是设置命名空间，同一份列表会出现在每个连接到同一 Host 的浏览器中。

提示词正文以明文形式保存在设置文档中。提示词库不做任何加密，也不做任何密钥处理，因此含有凭据的提示词会以明文形式留在磁盘上，任何能读取用户 `settings.yaml` 的程序都能读到它。该功能面向可复用的指令设计，而不是面向密钥。

在设置文档不可写的场合——内存模式与远程设置——提示词库是不可用而非降级，界面会明确说明，而不是接受它无法保留的编辑。

顺序即数组顺序，且本包只提供创建、编辑与删除，因此用户需要直接编辑文档来重新排序。搜索是在有界内存列表中对标题与正文进行不区分大小写的子串匹配，没有排序打分也没有标签；这两处缺口都记录在[包 README](../../../../packages/client/ui-prompt-library/README.zh.md) 中。
