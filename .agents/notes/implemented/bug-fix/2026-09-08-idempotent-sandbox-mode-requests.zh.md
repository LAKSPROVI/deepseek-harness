# Agent Note: 幂等的同模式沙箱请求

Status: implemented

[English](2026-09-08-idempotent-sandbox-mode-requests.md) | 中文

## 问题

工具 schema 属于全局注册表，而生效的沙箱模式属于具体会话。因此，已使用 `danger-full-access` 的会话仍会暴露 `sandbox_permissions: "danger-full-access"`。部分提供方即使收到省略冗余字段的指令，也会填充所有可选工具参数。严格加宽校验器会在执行前拒绝这种同模式请求，使无害的提供方序列化选择导致 agent 陷入重复工具失败，尽管调用并未请求任何权限变更。

## 决策

当请求模式属于 schema 允许的目标且等于调用的生效模式时，`approveEscalation` 将其视为幂等无操作。它不咨询审批服务，直接返回生效模式，工具随后在既有策略下执行一次。该例外仅适用于封闭的 `ESCALATION_TARGETS` 词汇；更窄目标、作为请求目标的 `read-only` 或任何未知值仍在执行前失败。严格更宽的请求继续使用既有审批流程与单次调用授权。

这种规范化修订了[原始沙箱决策](../feature/2026-07-06-sandbox.zh.md)中的非加宽情形，并保留在共享沙箱 Service Definition 中，使 bash、PowerShell 与进程内文件系统消费方不会分歧。它不改变会话状态，不记录审批事件，也不授予调用尚未拥有的能力。

## 曾考虑的替代方案

**继续拒绝所有非加宽请求。** 已否决，因为提供方可能序列化可选 schema 字段，即使其推理与 schema 都将这些字段标为可选。重复错误无法教会确定性输出该字段的提供方将其省略，而相等模式不会跨越安全边界。

**组合默认值为 `danger-full-access` 时隐藏升权字段。** 已否决，因为生效模式可由每个会话覆盖。按默认值派生的静态 schema 会从同一组合中的更窄会话移除其升权手段。

**忽略所有非加宽目标。** 已否决，因为更窄或未知目标不是当前权限的冗余表示。继续故障关闭这些请求可保留执行时校验边界。

## 后果

提供方生成的、与活动模式相同的 `sandbox_permissions` 不再阻止命令或触发审批提示。单元覆盖固定两种 schema 合法的相等模式，工具家族测试证明调用无需审批并使用未变模式执行，更窄或无效目标仍被拒绝。模型仍可能产生不必要参数，这些参数继续保留在持久工具调用中供诊断。
