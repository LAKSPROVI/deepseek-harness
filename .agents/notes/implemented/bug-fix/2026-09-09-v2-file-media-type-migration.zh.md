# Agent Note: V2 历史文件媒体类型迁移

Status: implemented

[English](2026-09-09-v2-file-media-type-migration.md) | 中文

## 问题

部分已发布的 V2 Session 在 `file` 内容块中记录了包含 `mediaType` 的附件。V2 到 V3 的源审计在这些 Session 出现之后才引入，只接纳 `attachmentId`、`name` 和 `bytes`。因此，即使该字段只是文件描述且不携带 Session 引用，完整的历史对话仍会在恢复时被拒绝。

## 决策

V2 到 V3 的源审计仅在 `attachment.mediaType` 为字符串时接纳该可选字段。迁移会在每个已审计内容所有者中原样保留它，包括拼接的 agent inbox 消息。它不会推断媒体类型、修改附件元数据或重写压缩的源工件。

## 曾考虑的替代方案

**在迁移中删除 `mediaType`。** 已否决，因为迁移必须保留历史请求语义和附件元数据；删除该字段会为了绕过准入规则而改变有效对话。

**接纳任意 `mediaType` 值。** 已否决，因为该可选历史成员仍是归本格式所有的元数据。要求字符串可接纳已发布的表示，同时继续拒绝畸形的持久数据。

**继续拒绝该字段。** 已否决，因为这会将一个非坐标的历史注释变成原本完整 Session 的永久恢复失败。

## 后果

带有字符串文件媒体类型的历史 V2 对话会在不改变源文件的情况下以 V3 重新打开。聚焦迁移覆盖证明了 `agent/inbox/spliced` 中的保留，并保持对非字符串值的拒绝。其他未知附件成员、未知内容种类和原生 V3 扩展规则保持不变。
