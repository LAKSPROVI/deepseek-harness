# Agent Note: Router availability controls selectable models

Status: implemented

[English](2026-10-07-router-live-catalog.md) | 中文

## 问题

当运行中的路由同步器读取延迟监视数据、写入已被导入的旧设置文件或拒绝空列表时，不可用模型仍可能保留在选择器中。pi-ai 适配器也拒绝零模型的自定义路由，因此完全中断时无法撤回模型。

## 决策

可选的[同步器](../../../../scripts/sync-router-live-models.mjs)读取经过认证的严格目录，并要求新的 Anthropic 文本、工具及流式语义证据。它通过检查修订号的 Settings RPC 仅更新已有提供方的模型列表，备份活动配置并按准确 ID 保留模型选项。空目录或未获确认的目录会撤回全部可选模型。明确声明协议和端点的自定义路由允许零模型；内置目录提供方保留原有默认行为。

监视进程默认每 30 秒轮询，并由同一个所有者处理手动刷新请求。状态读取器使用当前周期的有效期限和经过清理的错误，所以历史日志不能覆盖已恢复的状态。启用此模式的运行时还会过滤原生目录，并拒绝未获确认模型的解析或调用。状态文件变更和过期计时器会通知原生模型目录，即使监视进程停止也有效；会话选择和已经运行的流保持不变。

## 考虑过的替代方案

**失败时保留旧列表。** 这会在中断期间将未获确认的模型显示为可用，违背所需可用性契约。

**写入旧设置文件。** 当前 Settings 服务会把旧文件导入配置补丁；之后的写入不一定触达活动消费者。RPC 提供修订检查和原生变更事件。

**复制 OpenAI 客户端目录。** Anthropic 工具和流式响应需要单独证据。一般的成功结果或能力声明不能证明此客户端协议。

## 影响

暂时的目录失败可能导致恢复前没有可选模型。现有会话选择显示为不可用，不会被重新路由。刷新具有有限的轮询延迟，不保证提供方未来的正常运行。停止的本地后端恢复前不能接受变更。[使用说明](../../../../docs/user/router-live-catalog.zh.md)、CLI 传输、实时配置及状态读取回归测试定义了受支持的流程。


协议修正：同步遵循已有路由 API（`anthropic-messages` 或 `openai-completions`），并要求该协议的证明。并发协议修改会重新获取证据。临时网络故障、超时或 5xx 仅重试一次并使用新响应；仍失败则撤回选项，证明和租约期限不变。这支持 Ghost Opus 原生盲读已通过的 OpenAI 路径，同时保留修订检查和逐模型选项。部署和协议修改仍需要安装环境要求的操作授权。
